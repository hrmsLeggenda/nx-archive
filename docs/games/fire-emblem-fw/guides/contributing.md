# 万缕千丝 Wiki 页面维护

本文说明本站维护流程，不提供新的游戏结论。

## 创建页面

从游戏 Wiki 导航进入[创建页面](../edit)，选择攻略、资料条目、地图说明或补充模板。路径必须位于本游戏目录内；填写标题、分类、平台、版本、剧透程度、核对日期和资料来源。未知游戏版本写“未确认”。

编辑正文后查看预览与差异，填写编辑摘要，再检查主线是否已有同路径文件。内容默认保存为浏览器本地草稿，可复制或下载 Markdown。

## 修改页面

普通攻略上方提供“编辑页面”，载入已发布原文。结构化字段与 Markdown 内容同步；原有其他字段保留。已有页面路径在站内固定，重命名在 GitHub 完成，并同步修改关联链接。

自动生成的人物、职业、地点、物品和任务页通过“补充或勘误”创建独立补充页。补充内容保存在 notes 目录，构建重新导入不会覆盖。补充页发布后，原条目显示回链。若要修正导入数值，请同时修改已核对的数据来源或构建器，不能仅用补充文字替代数据修正。

## 提交与发布

复制完整 Markdown 后点击“前往 GitHub 提交”，在 GitHub 粘贴文件内容、填写编辑摘要并创建独立分支与 PR。该按钮只打开 GitHub，不会自动保存或发布正文。Actions 完成测试和构建，主线合并后部署；分类与搜索在构建时自动更新。

冲突检查比较当前主线文件与编辑基线。检查无法连接时，界面会明确说明；须在 GitHub 核对最新文件再提交。草稿若基于旧版，会提示合并差异。旧版本可从历史中复制，再导入编辑器作为一次新修改提交。

## 来源记录

每项事实应注明路线、阶段、章节、难度、版本和可查来源。社区整理、网页核对与游戏实测分别说明。未知刷新、坐标和随机权重继续标为未知；不要根据空字段推断不存在。

## 编辑结构化字段

人物、职业等自动生成条目上方提供“编辑结构化数据”；资源和任务列表可逐条进入勘误。选择要覆盖的字段，核对导入基线与有效值，填写修正、证据、日期、版本和原因。身份、原名和关联键保持稳定。

完成校验后复制或下载完整 JSON，通过 GitHub 分支与 PR 更新指定勘误文件。取消某字段的覆盖会恢复当前上游值；取消全部覆盖仍保留文件与历史。上游更新后人工修正继续生效，变化字段会提示复核；确认新的基线必须重新核对证据。
