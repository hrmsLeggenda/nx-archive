# 贡献指南

## 如何更新攻略

在 GitHub 创建分支，编辑 `docs/games/<游戏目录>/` 中的 Markdown，提交 Pull Request。Actions 自动测试与构建，合并后按部署配置发布。无需本机开发环境。

## 内容标准

- 使用自己的文字撰写，注明游戏版本、平台、验证日期和资料来源。
- 在文章开头标注剧透程度；未经确认的信息写明“待验证”。
- 地图图像须有使用授权；当前示例图为原创示意，不含真实游戏点位。
- 新增游戏时更新 `docs/data/games.json`，创建游戏首页和攻略条目。

## 地图数据

示例位于 `docs/games/<游戏目录>/data/*.json`。坐标使用 0–100 的百分比，点位 ID 必须唯一。正式地图可更换组件中的底图，同时保持相同坐标体系；多层地图与账号同步是后续迭代项。

## 游戏 Wiki 的归属

每个游戏在 `docs/games/<slug>/` 内维护首页、攻略、地图和数据；分类在 `docs/data/wikis.json` 中定义。文章与地图必须留在所属游戏目录，关联链接也应指向同一 Wiki。真实地图标明底图与坐标来源，阅读布局必须注明不是地理位置。

## 站内创建与编辑

先进入目标游戏 Wiki，使用导航中的“创建页面”选择模板。普通页面上方的“编辑页面”可载入已发布原文；页面分类、别名、平台、版本、剧透和来源字段与 Markdown 同步。

草稿仅保存在当前浏览器。可恢复、导入旧版 Markdown、复制或下载。预览支持常见 Markdown；HTML 和 Vue 组件显示为文本，正式效果请查看 Actions 的 wiki-preview 产物。

完成字段校验、编辑摘要和主线冲突检查后，点击“前往 GitHub 提交”。复制完整 Markdown，在 GitHub 粘贴内容并创建分支与 PR。此按钮不会自动提交，草稿保存也不代表已发布。

历史、旧版恢复和重命名入口跳转 GitHub；恢复时复制旧文再导入编辑器。重命名需要同步修改链接。自动生成条目通过独立补充页维护，修改数值则需更新结构化来源记录；不要直接编辑生成目录。
